# Golden datasets

Reference inputs and outputs generated by the real **pyFAI 2026.5.0** on
**Linux x86_64** to validate the rsFAI Rust port; `datasets_peaks/` and
`datasets_ringsearch/` come from **pyFAI 2026.9.0**, whose `Bilinear.local_maxi`
Hessian fix rsfai-peaks follows (each `manifest.json` records its version and
platform). See [`../doc/bit-exact-ladder.md`](../doc/bit-exact-ladder.md) for
what each tier must satisfy.

Linux is the canonical platform. The exact gates bind to the generating libm
(glibc here, which Rust's `std` also calls on Linux): against goldens made on
macOS (Apple libm) the bbox `sum_*`, calcfrom, fiber and OpenCL gates differ by
1–88 ULP and 12 of the workspace tests fail, and the converse holds on a Mac.

## Regenerate

The `pyfai2026.5` micromamba env holds the wheels pinned in `requirements.txt`
(PyPI manylinux, x86-64 baseline, so no FMA contraction; `pyopencl` for the
OpenCL goldens, generated on an NVIDIA RTX 5000 Ada):

```sh
micromamba create -n pyfai2026.5 python=3.12
~/micromamba/envs/pyfai2026.5/bin/python -m pip install -r golden/requirements.txt
OMP_NUM_THREADS=1 ~/micromamba/envs/pyfai2026.5/bin/python -I golden/gen_golden.py
```

`OMP_NUM_THREADS=1` is mandatory: it removes OpenMP reduction nondeterminism so
the accumulation order is reproducible (the bit-exact precondition).

Each generator also sets `NPY_DISABLE_CPU_FEATURES` to NumPy's AVX512 targets
before importing numpy: on an AVX512 CPU those kernels compute `power`,
`arctan2` and `arccos` with SVML, which is not libm-exact.

## What's committed vs regenerated

Each `datasets/<config>/` directory is self-contained. To keep the repo lean
(per-pixel arrays are ~100 MB/config), the `.gitignore` commits only:

- `manifest.json` — config + provenance (pyFAI/numpy versions, platform,
  `OMP_NUM_THREADS`, method tuple, per-array dtype/shape, ULP budgets).
- `geometry.poni` — the geometry used.
- `out_*.npy` — the golden **output** curves (radial, intensity, sigma, count,
  sum_signal, sum_variance, sum_normalization[2], std, sem). KB each.

The large per-pixel arrays — `image`, `mask`, `pos0_center`/`pos0_delta`,
`chi_center`/`chi_delta`, `corners`, `preproc`, `solidangle`, `polarization`,
`csr_*` — are **gitignored and regenerated** by `gen_golden.py`. They are needed
for the Tier-A/Tier-B per-pixel tests (M1–M6); run the generator once locally
before those tests. (Future: move them to git-LFS once a remote is configured.)

## Dataset naming

`<detector>__<split>-<algo>-<impl>__<unit>__npt<N>__err<model>`, e.g.
`Pilatus1M__bbox-csr-cython__2th_deg__npt1000__errpoisson`.
